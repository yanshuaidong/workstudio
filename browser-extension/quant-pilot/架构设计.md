# Quant Pilot 浏览器扩展 — 架构设计

本文描述 **东方财富列表数据采集** 插件的分层职责、运行期数据流，以及与本仓库 **`backend/` FastAPI**（见 [`backend/架构设计.md`](../../backend/架构设计.md)）的唯一对接方式。Plasmo 工程目录以仓库内实际为准（例如 `v1/quant-pilot` 或 `browser-extension/quant-pilot`）；扩展只认 **`backend/`** 提供的 HTTP 契约，**不**再对接任何其它本机采集守护进程或旧版 HTTP 服务。

---

## 1. 目标与范围

- **目标**：在东方财富指定列表页上，可靠截获 `qt/clist/get`（及同类列表 JSON）响应，按页抓取结构化行数据，并在用户可控的前提下写入本机 **标准化业务表**（与远端 MySQL 逻辑模型一致），必要时再触发 **本地 SQLite → 远端 MySQL** 的显式同步。
- **非目标**：后端不承担「源站点 JSON 字段 → 库列」映射；**字段对齐与清洗在扩展侧完成**（若编排状态在服务端，仍由 **`backend/`** 承载，而非第二套 HTTP 服务），与 [`backend/架构设计.md`](../../backend/架构设计.md) 第 1 节「数据源」约定一致。
- **范围**：Chrome Manifest V3 扩展（Plasmo）中的内容脚本、Service Worker、扩展页 UI；**不包含** FastAPI 服务实现细节（见后端文档）。

---

## 2. 在整体系统中的位置

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 东方财富页面（沪深列表 / 个股资金流等）                                     │
│   MAIN world：in-page 网络钩子（fetch/XHR 补充路径）                        │
│   ISOLATED：内容脚本 — DOM 分页、与 SW 消息                                 │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ chrome.runtime / messaging
┌───────────────────────────────▼─────────────────────────────────────────┐
│ Service Worker（background）                                               │
│   · chrome.debugger：Network 监听 + getResponseBody（主采集路径）          │
│   · 会话：翻页间隔、超时、页码对齐、可选与 backend 编排 API 联动               │
│   · HTTP 客户端：向 `backend/` 提交页数据、健康检查、可选编排轮询（见第 7 节）   │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ HTTP → 本机
┌───────────────────────────────▼─────────────────────────────────────────┐
│ `backend/` FastAPI（本机唯一采集写入网关）                                  │
│   · `GET /health` — SQLite / MySQL 探活                                      │
│   · `/api/v1/local/...` — 写入/查询 `database/stock.sqlite` 三张业务表       │
│   · `/api/v1/mysql/...` — 直连远端 MySQL 同源 CRUD（按需，扩展侧通常写 local）   │
│   · `/api/v1/sync/...` — 按交易日将本地表批量 upsert 到远端（显式触发）            │
└─────────────────────────────────────────────────────────────────────────┘
```

与后端的分工：

| 层级 | 职责 |
|------|------|
| **扩展** | 页面内可靠取证、分页自动化；将 **已映射为库语义** 的行或批次提交 **`backend/`**；控制台展示健康与写入结果（数据取自 OpenAPI 约定端点或后续编排接口）。 |
| **`backend/`** | 对 `stock_basic_info` / `stock_daily` / `stock_individual_fund_flow` 提供 **local/mysql** 双路径 CRUD；**不**内置东方财富字段映射；提供按交易日的 **sync**（SQLite → MySQL）。采集编排（任务 ID、分页进度聚合等）若需要，**在同一 `backend/` 进程内扩展路由与表**，扩展只与此服务通信。 |

## 3. 技术选型

| 方面 | 选型 | 说明 |
|------|------|------|
| 平台 | Chrome MV3 | Service Worker 替代持久 background 页 |
| 框架 | Plasmo | 多入口（background、contents、tabs）与构建管线 |
| UI | React + Ant Design | 采集控制台（如 `tabs/collector`） |
| 页面注入 | `chrome.scripting` + **MAIN world** | 在页面上下文拦截 fetch/XHR，与 ISOLATED 内容脚本解耦 |
| 主采集 | `chrome.debugger` | 对目标 tab 启用 Network，读取响应体；规避部分 SPA 封装限制 |

**权限语义**：`debugger` 用于读取网络响应体；首次使用需用户授权。其余 `tabs`、`storage`、`scripting` 等用于打开采集页、会话状态与注入。

## 4. 进程与分层职责

### 4.1 In-page 钩子（MAIN world）

- **职责**：在页面 JavaScript 环境拦截匹配的 `fetch` / `XMLHttpRequest`，将响应体副本通过 **自定义 DOM 事件** 等机制投递给内容脚本。
- **定位**：相对 `debugger` 的 **补充路径**（例如部分请求未出现在调试器回调时的兜底）；**不作为唯一可信来源**。

### 4.2 内容脚本（ISOLATED）

- **职责**：订阅 in-page 事件并转发至 SW；识别列表 **分页 DOM**、触发「下一页」、**页码对齐**（含异常页码回退后的 `GO_TO_PAGE` 类逻辑）；将业务无关的噪声 URL 参数剔出以利于去重（参见 `lib/qt-clist.ts` 一类模块中的约定）。

### 4.3 Service Worker（background）

- **职责**：挂载/解除 `chrome.debugger`；维护 **采集会话**（tabId ↔ datasetKey、采集批次标识、翻页状态）；调度 **翻页间隔与超时**；向 **`backend/`** 上报页数据与健康探测。若产品需要「服务端驱动打开标签、启停采集」，由 **`backend/` 提供编排 API**（如长轮询或 WebSocket），扩展内实现对应的 command dispatcher，**不**依赖仓库外或历史进程的私有协议。

### 4.4 扩展页 UI（如 `tabs/collector`）

- **职责**：人机交互：选择日期/任务、展示批次进度与 sync 结果、健康检查提示；通过 messaging 或直连 **`backend/`** 拉取 OpenAPI 暴露的聚合数据（「仅 SW 调后端」与「UI 也直连」二选一，需统一鉴权与 CORS）。

## 5. 数据采集通路

### 5.1 主路径：Debugger

1. 对目标 `tabId` 调用 `debugger.attach`，启用 `Network` 域。
2. 过滤与东方财富列表 API 匹配的 URL（如路径包含 `qt/clist/get` 且查询参数包含 `pn`/`pz`/`fs`/`fields` 等）。
3. 在响应完成事件中 `Network.getResponseBody` 取正文，交给 **`parseQtClistResponse`** 同类逻辑解析为 **Capture**（含当前页 `pn`、行数组、总页数推断字段等）。

### 5.2 补充路径：In-page 拦截

- 与主路径并行存在时，需在 SW 侧 **按 URL 语义去重**（见 `clistCaptureDedupeKey` 一类稳定键），避免同一页重复上报。

### 5.3 分页与进度

- **List 分页基础设施**（`background/list-auto-pagination.ts`、`pager-infrastructure.ts`）：在捕获上一页响应后，根据 `pn` / `total` / `pz` 计算下一动作；异常时 **reload 或跳转到指定页**；遵守 `MIN_PAGE_INTERVAL_MS` 等常量，降低风控触发概率。

---

## 6. 数据与映射边界

- **扩展输出** 应尽量已是后端 **Pydantic / 表列** 可接受的形态（蛇形命名、日期 `YYYY-MM-DD`、数值单位与远端字段说明一致），参见 [`database/远端数据库字段说明.md`](../../database/远端数据库字段说明.md)。
- **`qt/clist` 原始 `diff` 数组** → 业务行的映射在 **扩展或编排层** 完成；后端 **只校验与持久化**，不在 Router 内维护东方财富代号字典。
- **数据集区分**：例如沪深日线列表与个股资金流列表对应不同 `dataset_key`，解析与映射表可集中在 `lib/datasets.ts`（或等价模块）中配置。

---

## 7. 与 `backend/` 的 HTTP 契约（唯一对端）

- **基址**：由环境或扩展内配置提供，默认与后端文档 **4.1** 一致（例如 `http://127.0.0.1:8000`）。须在扩展 **`host_permissions`** 中声明该来源，并与服务端 CORS 策略一致。
- **健康检查**：`GET /health` → 返回 `sqlite`、`mysql` 探活结果（见后端实现）。
- **写入本地库（主路径）**：扩展将映射后的数据提交至 **`/api/v1/local/...`**：  
  `stock-basic-infos`、`stock-dailies`、`stock-individual-fund-flows` 等，方法语义以后端 OpenAPI 为准（`POST`/`PUT`/`PATCH`/`GET`）。高吞吐场景应优先使用或推动落地 **`bulk`/`upsert` 专用端点**（后端文档 §6.4）。
- **远端 MySQL**：扩展 **通常不直接写** `/api/v1/mysql/...`；由用户在控制台或服务端脚本触发 **同步**：  
  `POST /api/v1/sync/stock-daily/{trade_date}`、  
  `POST /api/v1/sync/stock-individual-fund-flow/{trade_date}`。
- **编排与仪表盘**：任务 ID、分页批次进度、当日汇总等 **若需要**，应在 **`backend/` 内** 增加表与路由（与三张业务表并存），扩展只调用该 **同一基址** 下的 OpenAPI；**禁止**再引入第二套本机 HTTP 采集服务作为写入网关。

**配置**：`BACKEND_BASE_URL`（或等价键）应唯一；内容脚本与 SW 共用同一配置源（如 `storage` 或构建期注入），避免分叉。

## 8. 源码目录与演进关系

| 路径 | 说明 |
|------|------|
| **`v1/quant-pilot`** | 当前仓库中的 **Plasmo 源码树之一**（background、lib、tabs 等）。 |
| **`browser-extension/quant-pilot`** | 可与打包输出、文档路径对齐；最终以单一 Plasmo 工程为准合并。 |

| 模块 | 角色 |

## 9. 安全与隐私

- 扩展仅在声明的 **东方财富域** 与本机回环地址上持有 `host_permissions`。
- **凭证**：后端若开启鉴权（API Key / JWT），扩展应通过 **安全存储** 或用户单次输入获取，不写入公共 gist；本文不规定具体密钥分发流程。
- **调试器**：仅应在用户明确启动采集时对目标 tab 附加，任务结束后应 **detach**，避免长期占用。

---

## 10. 演进清单（与后端对齐）

1. **批量 upsert**：扩展按页组包 → `POST` 至 `local` 侧 bulk 端点（或与后端协同定义），降低往返。  
2. **sync 触发策略**：按交易日完成后由 UI 或策略自动调用 §6.5 同步接口，并展示 `rows_read` / upsert 结果。  
3. **编排内聚**：任务与进度状态 **只在 `backend/`** 持久化；扩展 HTTP 客户端只指向 **`BACKEND_BASE_URL`**。  
4. **鉴权**：若生产环境启用 API Key / JWT，`backend/` 与扩展侧存储策略一次说清楚（不在本文展开实现细节）。
