# A 股日线数据收集模块说明

本扩展新增 **A 股日线数据收集** 能力，下文约定用词与流程。

## 术语

**当天时间**  
指设备上的真实日历日期与时间。

**交易日**  
中国 A 股市场实际开市、有成交的日期：通常为周一至周五中的开市日；不包括周六、周日、国家法定节假日及交易所公告的休市日。**是否交易日以项目内的 JSON 日历为准**。

**自动化收集时间**  
默认在每个 **交易日 16:00** 触发采集。可在自定义设置，格式为 **小时 + 分钟**。

**目标页面**  
需要从中抓取股票相关数据的网页，例如：

- https://quote.eastmoney.com/center/gridlist.html#hs_a_board  
- https://data.eastmoney.com/zjlx/detail.html  

**上报日（页面数据时间）**  
标识「本次采集对应哪一个交易日的页面数据」，用于校验上报日期是否合理（例如避免在非交易日却把上一交易日的数据误判为「当天」等错乱）。


## 为何需要「上报日」变量

目标站点通常只展示 **最新交易日** 的数据，**无法在页面上按历史日期逐日回放补采**。因此本系统是 **按最新交易日自动采集**，而不是「任选历史日期回放采集」。设置上报日便于核对：**本次上报对应的交易日是否与页面实际一致**，避免出现例如在周日仍把上周五数据误当作「当天」之类的逻辑错误。

## 数据流向

网页端（交易日对应的数据）→ **本地数据库（中转）** → **远端数据库**。


## 页面数据时间与「当天」的关系

- **若当天是交易日**：页面展示的一般为 **当日交易日** 的数据。  
- **若当天不是交易日**（周末或长假等）：页面展示的仍是 **上一交易日** 的数据；此时应结合日历与上报日逻辑，区分「自然日」与「数据所属交易日」。

## 运行时需要关注的状态

**目标页面**

- 未打开与已打开时的行为提示、采集前置条件。  
- 当前加载与健康状态：首页/尾页/当前页码；接口是否有返回，是否因风控而无数据。

**本地数据库**

- 已持久化到第几页、累计条数。  
- 同步进度及其它本地状态（中转阶段）。


## 界面与操作

### 开发调试

- **测试按钮**：不等待定时触发，立即执行一次自动化采集流程。

### 日常业务

- **是否开启自动采集** 开关。  
- **自动化收集时间** 选择器。  
- **采集进度** 展示。

### 自动化采集与本地库

采集开始前会先检查本地数据库，只有两种情形：

1. **本地无数据**：从第一页开始采集。  
2. **本地已有数据**：在已有记录之后继续追加（具体为：先跳到应继续的页码，再按「下一页」递进）。

采集策略为 **每抓取一页即写入本地数据库一页**，以降低中断导致的数据丢失。

### 风控识别与处理

**如何认定触发风控**（典型表现）：

- 接口不再返回有效数据；或  
- 页面上找不到上一页、下一页等分页控件。

**处理方式**：暂停采集，界面提示「被风控」，并提供 **继续** 按钮。待人工处理（如换网络、降频等）解除限制后，点击 **继续** 恢复。

### 翻页间隔（防风控）

页面存在风控策略时，需配置两项：

- **固定间隔**（秒，默认3秒）  
- **随机间隔范围**（秒，默认3秒）：在区间内按步长 **0.1** 随机取值，再叠加到固定间隔上。

示例：**固定 3 秒 + 随机 0～2 秒**（步长 0.1），则每次翻页前等待约为 `3 + rand(0, 2)` 秒（如 3.1、4.0、5.0 等）。

再示例：**固定 4 秒 + 随机 0～5 秒**，即每次等待 `4 + rand(0, 5)` 秒（如 4.1、6.3、9.0 等）。两项参数均可在界面中调整。

### 采集完成后的校验

- 以 **数量（总数）** 为主，核对是否遗漏、是否与预期一致。

### 同步到远端

前端在完成本地采集与校验后，请求 **本地后端** 将新增数据同步至 **远端数据库**。同步往往耗时较长。

**前端策略**：不必长时间阻塞轮询；本地后端接受请求后，可间隔等待并抽查远端（例如首次等待约 **10 分钟** 后查询远端条数是否与本地新增一致；若仍不一致，可再等待约 **10 分钟** 后 **最后一次** 复查）。若最终仍不一致，前端展示 **同步远端失败**；成功则展示 **同步成功**。


## 辅助功能

- **日期选择** 与 **清除本地库数据**：可按指定日期清除本地表中该日数据，例如清除「A 股日线」表中 5 月 7 日的记录。
