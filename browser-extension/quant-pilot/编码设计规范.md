# 编码设计规范

## 核心原则：变量优先

**先想清楚「有哪些变量、各自代表什么、如何变化」，再写流程与界面。**  
业务逻辑本质上由一组变量承载；变量设计对了，代码结构自然清晰。

## 落地要点

1. **命名即语义**  
   变量名应直接表达业务含义，避免 `data`、`temp`、`flag` 这类泛指。

2. **单一事实来源**  
   同一含义的状态只在一处维护；需要展示或派生时，明确是「读」还是「算」，不要多处各写一份。

3. **粒度合适**  
   宁可几个含义清晰的变量，也不要一个大对象到处透传却说不清谁在改哪一块。

4. **变化可追踪**  
   关键变量何时、因何被改写要可读（函数职责、数据流一眼能跟上）；避免隐式副作用堆叠。

5. **边界写清楚**  
   空值、加载中、失败、无权限等状态尽量变成显式变量或联合类型，而不是靠多重 `if` 猜。

## 自检一句话

> 若删掉所有函数，只看变量声明与类型，旁人能否大致看懂这件业务在管理什么？

能，则方向对；不能，先回到变量设计再写代码。
